# 协作流程

当前由两人协作：一人维护研究与代码，另一人负责服务器实验执行。两个项目保持独立：Aladdin 位于 `projects/aladdin/`，MLE-LEGO 位于 `projects/mle-lego/`，各自维护依赖、协议、测试和运行环境。独立 Aladdin 工作树仅作为来源和本地副本；总仓库中的对应目录是 GitHub 协作入口。代码修改和实验运行必须关联到同一个已记录的 Git 版本。

## 代码开发

维护者创建 Issue，说明所属项目、研究问题、协议限制、预期代码修改、测试和完成条件。实现者在分支上开发，运行本地测试并创建 Pull Request。维护者审查并合并后，才开展正式实验。

## 实验执行

维护者创建实验 Issue，指定不可变的 commit 或 tag、配置版本/哈希、数据清单/哈希、模型版本、随机种子、预算、GPU 分配、输出目录、冒烟测试命令、正式运行命令和审计标准。执行者准备服务器，先运行冒烟测试，再执行指定实验。协议或代码有变更时，必须先取得新的审查版本再继续。

执行者附上或链接 summary、进度/状态文件、日志、预检和审计输出，并提供证据归档的校验和。大型产物应保存在获批的产物存储中，而非 GitHub。使用所执行项目自己的报告模板：MLE-LEGO 模板位于 `projects/mle-lego/docs/`；Aladdin 模板位于 `projects/aladdin/docs/`。

## 审查与进度更新

维护者确认运行使用了指定代码版本和协议、审计通过且遵守最终测试限制后，才更新项目状态和总项目 README。执行者负责报告观察到的事实；研究解释须经审查后确定。跨项目整合应另建 Issue，并先约定带版本的接口。
