# 项目架构

## 研究范围

Data-Centric RSI 是研究总项目。Aladdin 和 MLE-LEGO 是总项目下相互独立的研究方向，并非同一实现的不同名称。在形成明确的整合契约之前，各自维护代码、环境、数据协议、实验和研究结论。

## 当前仓库边界

`projects/aladdin/` 和 `projects/mle-lego/` 分别包含 MLE-Aladdin 与 MLE-LEGO。Aladdin 目录已按维护者本地当前版本同步；后续协作更新进入总仓库对应子目录，并在代码提交中保留清晰的变更记录。两个目录都不是对方源码的依赖，也不共享运行时环境。

MLE-LEGO 内部设有共享运行时、三个技术模块边界和一个整合边界。当前先开展技术一 pilot；技术二、技术三已有框架模块，仍需完成真实任务适配与验证。当前没有总项目级共享代码包。

## 整合规则

- 默认将依赖留在各自项目中。
- 只有双方都确认具体用例、负责人、版本规则和兼容性测试后，才共享接口。
- 通过明确的 API 和数据契约整合；不要导入其他项目的私有模块或实验输出。
- 跨项目保留来源信息：代码版本、数据清单、模型版本、配置和产物标识。
- 保持每个子项目可独立安装和测试。

## 仓库后续扩展

总仓库现在作为两个项目的协同 monorepo 使用，但不把两个项目合并成一个 Python 包。若未来形成共同代码，应在经过审查的变更中提取至根目录 `shared/`，并提供迁移说明以及两个项目各自的测试。独立 Aladdin 工作树与总仓库中的 Aladdin 目录是两个副本；同步时先检查差异，避免互相覆盖未同步的修改。
