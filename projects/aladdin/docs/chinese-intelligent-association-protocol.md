# 第二场景：中文语境续写实验协议

**状态：** 本地实验设计稿；数据使用许可和真人反馈试点通过前，不作为正式运行协议。  
**任务名称：** 基于 LCCC 构造的中文语境续写（智能联想代理任务）。

## 1. 任务定义

给定一段对话上下文和用户已经输入的文字前缀，生成自然、相关的后续文字：

```text
上下文：明天什么时候见面？
已输入：明天下午我们
续写：在公司楼下见面。
```

本实验只研究中文文本续写，不加入拼音纠错、按键噪声、候选词转换或对话改写。由于数据来自对话语料而非输入法交互日志，论文中应称为“基于公开中文对话语料构造的智能联想任务”，不能据此声称验证了真实输入法采纳率、节省按键数或个人输入习惯适配。

## 2. 候选数据源与使用门槛

- 数据集：LCCC-base，官方项目说明提供 train、valid、test；Hugging Face 数据字段为 `dialog: list[string]`。
- 固定镜像：`silver/lccc@5bd582fa28cd7143f2f9c852e08e23089d677c44`。
- 固定文件：`lccc_base_train.jsonl.gz`、`lccc_base_valid.jsonl.gz`、`lccc_base_test.jsonl.gz`。
- 官方 Hugging Face 数据卡列出 train 6,820,506、valid 20,000、test 10,000 条对话。下载后必须核对实际条数和 schema，不以文档统计代替审计。
- 官方项目 README 声明数据集仅限科研用途；Hugging Face 镜像标注 MIT。由于上游还指出语料来自社交媒体且个人信息说明不充分，镜像许可标记不能单独视为底层文本权利和真人评审使用已获确认。

正式使用前须保存条款核验记录，确认研究用途、数据处理、人工展示及发布结果的边界；检查原文中的个人信息并执行过滤。不得将原始语料、含原文的样本或参与者反馈提交到 GitHub。若无法确认允许按本协议使用，则停止该数据集实验，先更换数据源。

参考：[CDial-GPT/LCCC 官方说明](https://github.com/thu-coai/CDial-GPT)、[LCCC 数据卡](https://huggingface.co/datasets/thu-coai/lccc)、[LCCC 论文](https://arxiv.org/abs/2008.03946)。

## 3. 样本构造

对每段原始对话，依次将第 2 条及之后的发言作为待续写文本；其之前的发言作为上下文。上下文最多保留最近 4 条，规则对所有数据划分保持一致。LCCC 的 `dialog` 字段没有显式说话人标记，因此不能确认每条目标发言都代表“当前用户正在输入”。数据审计须先检查发言顺序和格式；任务仍按通用对话语境续写解释，不推断用户身份或输入行为。

对原文先做 Unicode NFKC 规范化，删除汉字/CJK 标点之间以及汉字与中英文句读标点之间的分词空格，保留拉丁字母和数字之间的空格；再按 Unicode 字符位置生成 25%、50%、75% 三种前缀截断点。仅保留前缀和参考续写各至少 4 个字符的样本；截断点取整后重复时只保留一条。每条样本记录：

```text
record_id
source_dialogue_id
source_turn
context
typed_prefix
reference_continuation
cut_ratio
source_split
```

每个样本的 `source_dialogue_id` 是分组 ID。同一对话产生的所有截断样本必须始终留在同一数据角色中。LCCC 不包含实际键入前缀；`typed_prefix` 是从完整发言人工构造的代理输入，必须在论文中明确说明。参考续写只是一个自然表达样本，不是唯一正确答案。

## 4. 划分与少样本边界

1. 先规范化完整对话并按整个对话计算稳定哈希；完全重复的对话在跨 split 分配前合并。发生冲突时保留官方角色优先级最高的一份：test、valid、train。审计报告重复数和冲突数。
2. 保留 LCCC 官方 valid 为 development，官方 test 为 final test；两者不得进入合成、清洗、反馈选择、阈值调整或策略更新。
3. 只从官方 train 按固定种子和对话哈希分配 seed 与 feedback input pool。其余 train 对话标为未使用，不得作为额外合成示范、检索素材或训练样本。
4. 每次实验记录 seed 对话 ID 哈希、反馈池 ID 哈希、split seed、规则版本及各部分行数。开发和最终测试也按对话分组统计重叠，要求为零。
5. 初始技术试验可用 32 个 seed 对话检查数据和运行链路；这只是工程试点。正式 seed 数量和真人评价样本量，应在可用性/计时试点后预先确定，并按对话或参与者层级分析。

当前本地准备脚本执行跨官方 split 的规范化精确去重，并按邮箱、网址、中国大陆手机号和身份证号规则排除命中的整段对话。该启发式筛查无法识别所有身份信息，不能替代人工隐私审查。脚本不自动删除近似重复项；正式结果前须冻结并运行近似重复审计，报告方法、阈值、跨角色命中和排除数量。没有完成这些检查前，不得声称“近重复泄漏为零”。

## 5. 三阶段方法与对照

### 阶段一：数据合成

主方法固定为改造版 Self-Instruct：Qwen3-8B 从各条件共用的 seed 样本生成新的 `context + typed_prefix + continuation` 记录，保存生成策略、模型 revision、轮次、父样本 ID 和请求/token 成本。该方法针对续写任务做了适配，不称为原论文完整复现。固定流水线与递归流水线使用同一初始生成策略；递归组只可依据上一轮第三阶段反馈更新下一轮提示词、示范和生成配置。`seed-only`、`fixed-prompt` 和 Evol-Instruct 不属于本场景 RSI 主实验的必跑比较。development 与 final-test 内容不提供给生成器。

### 阶段二：数据清洗

主方法固定为确定性规则清洗：过滤空文本、格式错误、与输入前缀重复的输出、完全重复及 development 预检后冻结阈值判定的近重复项，并逐条记录原因。被拒绝样本保存在隔离池，供第三阶段按固定配额抽查；抽查反馈只影响下一轮清洗策略。当前主实验不使用 LLM 质量 judge，也不把自动规则判断称为人工确认的质量真值。

### 阶段三：数据选择与真人反馈

从相同 feedback input pool 和候选池中选择待评审样本。随机选择和不确定性选择作为基线，反馈价值选择作为 Aladdin 方法；三者使用相同候选池、标注流程和累计真人评审分钟。样本先被选择，之后才展示给参与者并收集反馈。选择方法比较期间冻结选择器自身的更新规则，避免混淆查询策略差异与选择器学习。

每条请求展示上下文、已输入前缀和同一输入下两个盲化候选，随机交换左右顺序。允许选择“A 更合适”“B 更合适”“都可以”“都不好”“无法判断”，并允许修改或填写简短原因。记录匿名参与者 ID、query ID、候选 ID、判断、修改、原因、开始/结束时间和实际评审秒数。先做小规模可用性与计时试点，再确定正式人工分钟预算和样本量。

## 6. 递归更新与系统对照

至少运行两轮；从同一套初始 baseline 和预算出发比较：

- `fixed-policy`：使用改造版 Self-Instruct、确定性规则清洗和反馈价值选择；三项策略保持初始版本，收集到的反馈不改变下一轮数据策略。
- `recursive-policy`：从相同三项初始策略开始，使用第三阶段反馈更新下一轮合成、清洗和反馈选择策略。

另外按主实验比较随机、不确定性和反馈价值三种样本选择策略；这是查询策略对照，不额外定义一套系统组。各组对齐可见 seed、候选生成预算、清洗方法、累计真人评审分钟、任务模型训练 token 和评价输入。每条样本先被选中，再收集人工反馈。保存反馈事件、更新前后策略版本及下一轮样本 lineage；反馈不足以支持合理变化时允许 no-op，不为了呈现递归而伪造策略变化。

## 7. 评价与结论边界

- **主要效果指标：** 对未参与更新的输入，真人盲评不同实验组模型的续写，报告偏好胜/平/负、无法判断比例及按对话和参与者聚类的不确定性。
- **反馈效率指标：** 实际评审分钟、有效反馈数、每分钟反馈量，以及同一人工预算下模型偏好变化。
- **次要自动指标：** 对参考续写的条件 NLL 或字符级指标可用于诊断，不作为续写质量的唯一结论，因为单一原文不是唯一正确答案。
- 用于策略更新的 feedback pool 与最终盲测参与者/输入分离；最终评价不回流到本轮更新。报告标注者分歧，不强行合并为单一客观标签。
- 本实验可支持“数据流水线在 LCCC 构造的中文语境续写任务上的可行性/效果”结论。真实输入法采纳率、按键效率和产品级个性化需要真实输入法交互数据或部署研究。

## 8. 实施顺序

1. 完成 LCCC 条款和隐私审查。
2. 下载固定版本并校验 manifest；运行：

```bash
python -m scripts.download_datasets --dataset lccc --confirm-research-terms
python -m scripts.prepare_lccc_association \
  --confirm-research-terms --confirm-privacy-review \
  --seed-dialogues 32 --feedback-dialogues 128
```

该准备器完成规范化精确去重、常见直接标识符启发式筛除、样本转换和对话分组。准备后的 manifest 会记录命中的标识符类别计数，但不会输出原文。近重复审计仍需独立完成。
3. 运行无 GPU 的数据准备试点，人工检查样本格式和截断质量。
4. 冻结数据规模、模型 revision、预算和评价 rubric。
5. 先完成阶段一合成方法比较，再实现阶段二清洗和阶段三真人反馈。
6. 组件冻结后运行多轮更新对照，并在独立输入上做人评。

当前 PRISM 实验结果不与本场景合并统计；本场景的数据适配器、真人反馈流程和实验 runner 尚未实现。
