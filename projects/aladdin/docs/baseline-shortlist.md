# Aladdin 对照方法候选清单

## 范围

本文为固定的三阶段研究流程整理对照方法，不改变三个阶段：

1. 数据合成。
2. 数据清洗。
3. 选择值得人工评审的数据并收集反馈。

只有第三阶段请求新人工反馈。第一阶段合成、第二阶段清洗都按自动策略执行；第三阶段优先选择反馈价值高、值得请人判断的候选。这里的“好”指适合优先评审，不代表已确认质量合格。反馈用于调整下一轮合成和清洗策略。RSI 循环连接三个数据操作，本身不是第四个数据操作。

本文是方案清单，不是预注册，也不表示这些方法已集成或经过实验验证。可行性试验后，须在协议中锁定具体模型、数据划分、预算、过滤阈值和实现版本。

## 方法选择原则

- 每种方法在同一阶段比较，并接收相同输入。
- 适用时固定基础模型、seed、候选池、训练预算和人工时间预算。
- 区分“挑选给人看的样本”与“挑选用于任务模型训练的数据”。
- 统计生成、自动评审、过滤、训练和第三阶段人工评审的全部成本。阶段一、二不得暗中加入人工筛选或校准。
- 历史标签回放只能作为反馈机制模拟，不能当作新收集的人工反馈或人工耗时测量。

## 分阶段对照建议

| 阶段 | 必要对照 | 目的与注意事项 |
|---|---|---|
| 数据合成 | 不合成；只用相同 seed | 检验加入生成数据是否有帮助。 |
| 数据合成 | 固定提示词合成 | 从相同 seed 出发，使用冻结提示词和匹配预算，是简单可复现的扩充基线。 |
| 数据合成 | 改造版 Self-Instruct | 有代表性的 seed 驱动数据生成方法。用于 PRISM 时需改造成任务输入/回答格式，并说明这是改造，不是直接复现原论文。 |
| 数据合成 | 改造版 Evol-Instruct | 任务可表示为 instruction/task-input 演化时，作为更强的合成参考。匹配操作预算并记录改造，不要称为直接复现 response 生成。 |
| 数据清洗 | 不清洗 | 估计未经处理的生成候选效果。 |
| 数据清洗 | 确定性规则 | schema/格式检查、精确去重和近重复检测；实现与阈值应冻结，并报告保留率、重复率和覆盖变化。 |
| 数据清洗 | 固定质量评分过滤（可选） | 检验语义质量过滤。可用冻结 rubric 的 LLM judge；分数只视为自动代理信号，不是真值。阶段二不请求人工校准/审计；若没有独立标注，不报告误删率或低质量残留率。AlpaGasus 可作相关参考，不是开放式生成任务的直接可用实现。 |
| 反馈选择 | 随机查询 | 人工时间预算相同条件下的必要基线。 |
| 反馈选择 | 贝叶斯/不确定性主动偏好学习 | 成熟的 pairwise 偏好查询方法族；实现可行时作为主要文献基线。 |
| 反馈选择 | 评审分歧 | 较简单的诊断基线。标签释放前冻结评审模型和提示词；分歧不等于正确性。 |
| 反馈选择 | 固定 embedding 空间的多样性选择 | 可选覆盖度基线，如 greedy k-center/core-set。经典证据多来自分类任务，应用到生成反馈需视为改造。 |
| 反馈选择 | Aladdin 的单位评审成本影响力 | 候选方法：优先请求预计能影响更多后续合成/清洗决策的反馈，并考虑预测评审耗时。与随机和贝叶斯/不确定性方法在相同实测人工时间预算下比较；分歧方法作为诊断。 |

### 实现注意事项

- 确定性数据处理可使用成熟的数据处理库。Hugging Face Datatrove 可作可扩展去重/过滤的工程实现参考，但它本身不是科学对照方法。
- 多个 LLM 提示词意见一致不能等同于正确。若以后要人工抽查清洗结果，应将抽查作为第三阶段反馈查询的一部分，并计入同一人工预算。
- 条件允许时可使用固定的开放模型作为自动质量评审。若使用托管评审模型，记录模型及版本、提示词、API 成本和调用日期，且不能让评审器访问 held-out 结果。
- 不同方法生成的训练集大小和训练 token 预算必须匹配，否则数据量增多可能被误认为选择或清洗效果更好。

## 系统级对照

| 组别 | 合成与清洗 | 反馈采样 | 反馈是否更新下一轮 |
|---|---|---|---|
| A. 仅 seed | 不合成、不清洗；只用 seed | 无 | 否 |
| B. 固定流程 | 固定合成和清洗 | 随机反馈；与 C 使用相同数量和时间预算。反馈可作训练监督，但不能修改合成/清洗策略 | 否 |
| C. 随机反馈 RSI | 与 D 使用相同初始合成/清洗 | 随机选择，人工时间预算一致 | 是 |
| D. Aladdin RSI | 与 C 使用相同初始合成/清洗 | 按单位评审成本影响力选择 | 是 |

主要比较：

- B 对 A：固定数据流程是否优于少量 seed。
- C 对 B：随机查询条件下，递归使用反馈更新策略是否有价值。
- D 对 C：递归流程中，Aladdin 反馈选择策略是否有额外价值。

若要声称反馈分别改善了合成和清洗，须增加两个机制消融：只更新合成、只更新清洗。没有这两个消融时，只能报告组合流程的效果，不能分别声称两个操作都已被证明有效。

## 指标

### 主要结果

在适用的 source group/user 划分下，对新输入上的任务模型输出做盲测人工偏好或 rubric 评价。评价集不能参与合成、清洗、查询选择和策略更新。除均值外，还要报告标注者一致性和不确定性。

### 阶段诊断

- 合成：候选独特率、任务/要求覆盖、重复率和生成成本。
- 清洗：保留率、重复率、覆盖变化、自动处理成本和固定 development 集的下游效果。若第三阶段抽查，再单独报告人工审计得到的误删率。
- 反馈选择：每人工分钟获得的有效反馈、实测评审时间、以及相同累计人工时间下的下游效果。
- 全流程：逐轮下游质量、生成/judge/训练成本，以及可归因于反馈的策略变化。

须在运行前定义“有效反馈”，例如反馈改变了 requirement state 或导致后续数据操作改变。不要看完结果再定义。

## 数据计划

不同数据源用于验证不同方面，不能混为同一任务：

- **PRISM**：适合用户关联的偏好与反馈回放。保留对话和用户边界；没有依据时不要把对话级评论分配到每条 response。
- **HelpSteer2**：提供 response 评分/偏好，适合受控反馈选择和评审器校准；它不能单独代表某一用户不断变化的要求。
- **CoAuthor**：提供真实写作交互和编辑记录，但接受、拒绝或修改本身不自动构成干净的偏好标签。

当前可行性方案以 PRISM 为主要数据源，按 `user_id` 切分，保证同一参与者的对话处于同一角色。HelpSteer2 用于受控回放/校准，CoAuthor 暂缓。其他数据集应按 source group 切分，例如 prompt family 或 writing project，并让派生/增强数据继承其 source group。

隐藏标签回放可以在查询被选中后再释放标签，从而比较查询策略；它不能证明真实人工耗时下降。要支持耗时结论，必须对新生成的候选开展单独的 live study，并记录每次评审时间。

## 当前决策

不把所有阶段方法做全因子组合。先在共享 development pool 上分别做小规模组件比较，每阶段冻结一个实用方法后，再做系统组 A-D 比较，以免模型训练和人工评审成本成倍增长。

首轮可行性试验的最小比较为：

1. 无合成、固定提示词合成和改造版 Self-Instruct。确认性合成比较在任务适配且实现可固定时增加改造版 Evol-Instruct。固定提示词是工程对照；Self-Instruct 和 Evol-Instruct 是文献合成对照。
2. 不清洗、确定性规则清洗；固定模型质量分过滤作为可选自动对照，不引入阶段一、二人工判断。
3. 随机、贝叶斯/不确定性偏好选择、Aladdin 单位评审成本影响力选择。分歧作为诊断；只有在候选池 embedding 表示可靠且查询预算允许时才加入多样性选择。
4. 按同一任务模型、候选预算、训练 token 预算和人工分钟预算运行系统组 A-D。

在确认性实验开始前，须冻结主要数据集、任务模型、人工反馈流程、自动 judge rubric、随机种子和各阶段预算。阶段一、二不加入人工标注；人工计时和反馈效用在第三阶段测量。

当前可行性设计已确定：PRISM 是主要人工反馈数据集，HelpSteer2 是受控回放/校准数据集，CoAuthor 暂缓。具体划分、阶段对照、系统组和预算见 `docs/feasibility-pilot-protocol.md`。这是一项方案决定，不是实验结果。
