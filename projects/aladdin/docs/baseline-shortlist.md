# Aladdin 主实验方法与基线

> 当前执行配置：第三阶段使用固定 Qwen3-32B（revision `9216db5781bf21249d130ec9da846c4624c16137`）模拟反馈，每组每轮按 `query_count_per_arm_round` 固定评审条数。下文人工分钟和真人效果属于后续真人验证协议，不能用于解释当前模拟结果。当前记录模型调用次数、token、耗时和失败尝试；final-test 使用 Qwen3-32B 自动盲评，真人入口作为可选功能保留。


## 范围

本文为固定的三阶段研究流程整理对照方法，不改变三个阶段：

1. 数据合成。
2. 数据清洗。
3. 选择值得人工评审的数据并收集反馈。

只有第三阶段请求新人工反馈。第一阶段合成、第二阶段清洗都按自动策略执行；第三阶段优先选择反馈价值高、值得请人判断的候选。这里的“好”指适合优先评审，不代表已确认质量合格。反馈用于调整下一轮合成、清洗和反馈选择策略。RSI 循环连接三个数据操作，本身不是第四个数据操作。

本文记录当前主实验采用的方法，不表示这些方法已经集成或经过实验验证。方法类别已经选定；具体模型配置、数据划分、预算、过滤阈值和实现版本仍须经过 development 预检，并在正式运行前冻结。

## 方法选择原则

- 运行方法对照时，同一阶段各组接收相同输入和资源预算；单组件比较不是 RSI 主实验的必跑项。
- 适用时固定基础模型、seed、候选池、训练预算和人工时间预算。
- 区分“挑选给人看的样本”与“挑选用于任务模型训练的数据”。
- 统计生成、自动评审、过滤、训练和第三阶段人工评审的全部成本。阶段一、二不得暗中加入人工筛选或校准。
- 历史标签回放只能作为反馈机制模拟，不能当作新收集的人工反馈或人工耗时测量。

## 已选方法

| 阶段 | 主实验采用 | 角色与边界 |
|---|---|---|
| 数据合成 | 改造版 Self-Instruct | 从少量 seed 生成新的任务输入和回答；固定策略组与递归组共用同一初始方法。属于任务适配，不是原论文完整复现。 |
| 数据清洗 | 确定性规则清洗 | 检查格式、空文本、无效续写、精确重复和近重复；保留隔离池及逐条原因。规则和阈值先在 development 预检，再冻结。 |
| 数据选择 | 反馈价值选择 | 整体对照和更新消融的共同初始策略，也是 Aladdin 待检验的方法；固定组不更新，递归组依据反馈更新。 |
| 数据选择 | 随机选择、不确定性选择 | 实验三的两个查询基线；与反馈价值选择使用相同候选池、真人反馈流程和累计人工分钟比较。 |

`seed-only`、固定提示词合成、Evol-Instruct、LLM 质量 judge、评审分歧和 embedding 多样性选择不属于当前主实验必跑组。若将来研究问题改为比较单个组件算法，再单独加入对应对照；不以这些扩展比较替代当前 RSI 主实验。

### 实现注意事项

- 确定性数据处理可使用成熟的数据处理库。Hugging Face Datatrove 可作可扩展去重/过滤的工程实现参考，但它本身不是科学对照方法。
- 多个 LLM 提示词意见一致不能等同于正确。若以后要人工抽查清洗结果，应将抽查作为第三阶段反馈查询的一部分，并计入同一人工预算。
- 当前主实验不使用 LLM 质量 judge 作为阶段二必需组件；若后续增加，须作为独立扩展，记录模型、提示词、API 成本，并将分数表述为自动代理信号。
- 不同方法生成的训练集大小和训练 token 预算必须匹配，否则数据量增多可能被误认为选择或清洗效果更好。

## 当前主实验比较

详细协议见 [`feedback-driven-update-experiment.md`](feedback-driven-update-experiment.md)。主实验分为三项比较，不把它们误写成数据流水线的三个操作阶段。

| 比较 | 方法 | 主要问题 |
|---|---|---|
| 整体对照 | 固定合成/清洗/反馈选择策略 vs 根据反馈递归更新三类策略 | 递归更新相对固定流水线是否带来额外收益？ |
| 更新消融 | 完整更新 vs 停止合成更新、停止清洗更新、停止反馈选择更新 | 每类策略更新分别起什么作用？ |
| 反馈选择 | 随机选择 vs 不确定性选择 vs 反馈价值选择 | 相同实际人工分钟预算下，哪种选择得到的反馈更有用？ |

三项比较都遵守同一阶段边界：合成和清洗自动执行；只有第三阶段选择查询并收集真人反馈；反馈只影响下一轮策略。整体对照中的固定组也使用同样的人工分钟预算和标注流程，但冻结数据策略，避免把反馈量差异当成递归更新收益。选择方法之间固定后续更新规则、候选池、标注流程和实际时间预算。

被清洗器拒绝的候选及拒绝原因必须保留在隔离池中，并从第三阶段划出预先固定的抽查预算；否则无法用反馈判断清洗器是否误删，也无法公平检验清洗策略更新。

## 指标

### 主要结果

在适用的 source group/user 划分下，对新输入上的任务模型输出做盲测人工偏好或 rubric 评价。评价集不能参与合成、清洗、查询选择和策略更新。除均值外，还要报告标注者一致性和不确定性。

### 阶段诊断

- 合成：候选独特率、任务/要求覆盖、重复率和生成成本。
- 清洗：保留率、重复率、覆盖变化、自动处理成本和固定 development 集的下游效果。若第三阶段抽查，再单独报告人工审计得到的误删率。
- 反馈选择：每人工分钟获得的有效反馈、实测评审时间、以及相同累计人工时间下的下游效果。
- 全流程：逐轮下游质量、生成/judge/训练成本，以及可归因于反馈的策略变化。

须在运行前定义“有效反馈”，例如反馈改变了 requirement state 或导致后续数据操作改变。不要看完结果再定义。

## 数据计划

不同数据源用于验证不同方面，不能混为同一任务：

- **PRISM**：适合用户关联的偏好与反馈回放。保留对话和用户边界；没有依据时不要把对话级评论分配到每条 response。
- **HelpSteer2**：提供 response 评分/偏好，适合受控反馈选择和评审器校准；它不能单独代表某一用户不断变化的要求。
- **CoAuthor**：提供真实写作交互和编辑记录，但接受、拒绝或修改本身不自动构成干净的偏好标签。

当前可行性方案以 PRISM 为主要数据源，按 `user_id` 切分，保证同一参与者的对话处于同一角色。HelpSteer2 用于受控回放/校准，CoAuthor 暂缓。其他数据集应按 source group 切分，例如 prompt family 或 writing project，并让派生/增强数据继承其 source group。

隐藏标签回放可以在查询被选中后再释放标签，从而比较查询策略；它不能证明真实人工耗时下降。要支持耗时结论，必须对新生成的候选开展单独的 live study，并记录每次评审时间。

## 当前决策

当前主实验采用改造版 Self-Instruct、确定性规则清洗，以及随机/不确定性/反馈价值三种查询选择方法。固定流水线与递归流水线使用同一初始组件；三类更新消融用于识别反馈递归更新的作用。阶段一和阶段二不加入人工判断，第三阶段先选出样本，再收集和计时真人反馈。

当前数据集可行性判断及使用边界见 `docs/feasibility-pilot-protocol.md`；具体主实验比较以 `feedback-driven-update-experiment.md` 为准。这是方案设计，不是实验结果。
