# Aladdin 实验设计与执行协议

## 当前最终实验结构

论文主实验固定为 5 个 Q。三个核心数据操作始终不变：数据合成、数据清洗、数据选择；变化的是是否允许这些操作根据反馈更新，以及有限反馈如何分配。

| 主 Q | 实验 | 要回答的问题 | 主要对照 |
|---|---|---|---|
| Q1 | 实验一：整体效果 | 完整的反馈驱动递归更新是否优于固定数据流水线？ | `fixed_policy` vs `recursive_policy` |
| Q2 | 实验二：更新机制 | 合成、清洗、选择三类更新各自贡献多少，是否有交互？ | 三因素 2^3 的 8 个组合 |
| Q3 | 实验三：反馈效率 | 有限反馈应该分配给哪些样本？ | 随机、不确定性、反馈价值选择 |
| Q4 | 实验四：少样本适用性 | 初始数据越少时，递归数据改进是否仍然有效？ | 不同初始数据量下的固定 vs 递归 |
| Q5 | 实验五：需求逐步明确 | 用户要求后来才逐渐明确时，系统能否适应新要求并保留旧能力？ | 固定更新、递归更新、完整要求参考组 |

Q1 验证整体是否有效；Q2 解释收益来自哪些更新；Q3 验证反馈预算如何分配；Q4 验证少样本场景；Q5 验证要求变化场景。清洗审计、模拟反馈与真人一致性、故障恢复和成本敏感性是支撑验证，不替代五个主 Q。

当前先为实验一至实验三提供 smoke：Smoke 仅验证协议执行与指标生成，不是研究效果证据。实验四的数据预算 runner 和实验五的需求释放 runner 已保留为实现草案，但暂不运行 smoke，待正式实验方案、预算、对照组和验收指标冻结后再执行。

## 研究对象

Aladdin 研究的是数据策略能否在任务反馈驱动下持续改进。每轮依次执行：

```text
少量 PRISM seed
  -> Qwen3-8B 合成候选
  -> 确定性规则清洗并隔离可疑样本
  -> 选择样本收集反馈
  -> 更新下一轮合成/清洗/选择策略
  -> 用已确认反馈构造训练集并更新 Qwen3-8B LoRA
  -> 在分组隔离的 development 数据上评估
```

更新对象是合成指导、清洗阈值和反馈选择权重等数据策略状态；Qwen3-8B 是执行下游任务并被训练的模型。反馈在样本选择之后收集。`final_test` 只用于协议和分析冻结后的独立盲评。

### 固定数据和模型

| 项目 | 规定 |
|---|---|
| 数据 | 固定 revision 的 PRISM；按 `source_group_id` 隔离 seed、development、final-test |
| seed | `data/processed/prism/seed.jsonl`；运行不得访问其他训练数据 |
| development | `development.jsonl` 与标签 sidecar；按 source group 再分 selector calibration 与 outcome evaluation |
| 任务模型 | 固定 revision 的 Qwen3-8B；所有组相同 LoRA、训练记录数、token 上限和训练参数 |
| 反馈模型 | Qwen3-32B 固定 revision，只能产生模拟反馈；不能称真人偏好或人工成本 |
| 训练预算 | 每 arm/轮最多 256 条、100,000 个训练 token、相同 max steps 与优化参数；记录实际值 |
| pilot | 默认单 seed 17、3 轮；用于流程验证和估算方差，不支持确认性结论 |
| 正式实验 | seed 数由 pilot 的 seed-level 配对差异做功效分析后预先冻结；不得把轮次当独立样本 |

## 共同实验纪律

1. 先验证数据 manifest、组间无泄漏、配置 revision、候选数量、反馈数量、模型服务和 GPU 训练。
2. 每次运行写入新的输出目录；保存配置快照、输入 SHA-256、代码 revision、环境版本、每轮策略状态、候选、清洗决定、查询、反馈 attempts、训练集、训练日志和 evaluation 结果。
3. 主分析单位是 seed。每个 seed 内先按预注册规则汇总轮次，再计算 arm 间配对差；报告每 seed 原始值、均值差、95% 区间及 wins/ties/losses。seed 数不足以做稳定推断时只报告描述统计。
4. 多个主要假设使用 Holm 校正；同时报告未校正和校正后的区间/检验结果。不得只挑有利轮次或指标。
5. 区分模型模拟反馈与真人反馈。Qwen3-32B 结果只用于系统工程和策略趋势；真人效率或真实偏好结论必须来自真人标注。
6. development outcome 仅供诊断。所有策略、阈值、随机种子、主要指标和分析脚本冻结后，才开启 final-test 盲评。

## QA-0：数据、清洗器与协议是否可靠

### 假设

实验数据分组和日志能够支持可复核对照；清洗器对预先定义的问题样本具有可测的查准率/查全率，且不会把去重规则误称为语义质量判断。

### 操作

1. 对 PRISM 原始记录按 source group 先切分，再构造 seed/development/final-test；记录各 split 的记录数、source group 数、标签比例、文本长度分布及 SHA-256。
2. 自动检查 group 交集为零、record ID 唯一、标签 sidecar 一一匹配、final-test 路径未进入训练 runner。
3. 建立清洗器审计集：从候选/PRISM 文本中按规则原因分层抽样，包含规则判定保留与隔离的样本。由至少两名独立标注者按固定说明标记“明显重复、近似重复、异常重复、格式/空样本、可用但被误删”；分歧由第三人仲裁。报告标注一致率与仲裁比例。
4. 固定阈值，在审计集上计算各原因的 precision、recall、F1、保留率、误删率和隔离率；另报告阈值网格敏感性，但不得用 final-test 调阈值。
5. 运行恢复/失败注入测试：模拟 API 超时、无效 JSON、非法枚举、部分轮次中断和 resume；检查每次请求与 token/耗时可追溯、已完成 query 不重复计费或重新收集。

### 对照与判定

- 对照：当前规则清洗器 vs 不清洗；审计指标按同一批候选配对计算。此 QA 评估清洗决策质量，不单独证明下游模型提升。
- 通过条件：数据不变量全部通过；每个失败/重试均有 attempt 记录；清洗混淆矩阵完整；误删和漏删可定位到样本与规则。
- 阈值不得凭空指定最低 F1。先用小型盲审估计可达性，再由研究者在正式标注前冻结最低可接受 precision/recall 及其理由。

### 报告

数据 split/哈希表；清洗混淆矩阵与按原因的 precision/recall/F1 表；阈值敏感性折线图；失败恢复审计表。

## QA-1：完整递归更新是否优于固定数据流水线

### 假设与主要估计量

在相同 seed、初始策略、候选预算、反馈预算和任务训练预算下，完整反馈驱动递归策略相比固定策略，能够提升后续 development 偏好准确率。主要估计量是每个 seed 最后一轮 outcome-evaluation pairwise accuracy 的 `recursive - fixed` 配对差；最终结论由独立 final-test 真人盲评验证。

### 组别

| 组 | 合成更新 | 清洗更新 | 选择更新 | 其他 |
|---|---:|---:|---:|---|
| `fixed_policy` | 关 | 关 | 关 | 每轮仍收集相同反馈并训练任务模型 |
| `recursive_policy` | 开 | 开 | 开 | 本轮反馈只影响下一轮 |

两组第一轮必须共享候选语义多重集和反馈标注；首轮训练数据、训练记录数及训练参数应匹配。若实际反馈分配在序列化后改变，运行应失败或明确记为 protocol deviation。

### 设计

- 先单 seed 完整 rehearsal，确认 3 轮、2 arms、每轮反馈队列全部完成、resume 正确、final-test 未读。
- pilot 完成后按 seed-level 配对差的标准差和预先确定的最小有意义差异 `delta_min` 做功效分析（双侧 alpha 0.05、power 0.80）；在运行正式实验前冻结 seed 数、seed 列表和分析脚本。
- 每个 seed 两组共享初始 seed groups；每轮候选数 32、选择并反馈 16 条；训练预算按共同设置执行。
- development 指标每轮均报告，但确认性 outcome 只采用预注册的最终轮指标，避免把轮次伪增样本量。

### 指标和呈现

- 主指标：最终轮 development pairwise accuracy 配对差；final-test 真人盲评 decisive win rate、both/neither/cannot-judge 比例和按 source group bootstrap 的 95% CI。
- 次指标：每轮策略版本变化、有效反馈率、候选保留/隔离率、生成/反馈/训练 token 与耗时、失败重试数、完成率。
- 图表：逐轮趋势折线（描述性）；seed-level paired dot/line plot；最终盲评胜平负及区间表；成本—效果表。

### 失败判据

关键预算不等、首轮训练集不匹配、反馈丢失/重复、final-test 提前读取或 run 未完整完成时，该 seed 不进入主要效应分析；报告偏离并用新 run 复现，不静默删除。

## QA-2：三类数据策略更新的主效应与交互作用

### 问题

合成、清洗、反馈选择策略更新分别带来多少收益？组合更新是否存在单模块实验无法解释的协同或抵消？

### 设计：完整 2^3 因子实验

使用 `configs/experiment-two-factorial.example.json`，每个 seed 运行 8 个组合：

| 合成更新 S | 清洗更新 C | 选择更新 Q | arm |
|---:|---:|---:|---|
| 0 | 0 | 0 | `fixed_policy` |
| 1 | 0 | 0 | `synthesis_only` |
| 0 | 1 | 0 | `cleaning_only` |
| 0 | 0 | 1 | `selection_only` |
| 1 | 1 | 0 | `synthesis_cleaning` |
| 1 | 0 | 1 | `synthesis_selection` |
| 0 | 1 | 1 | `cleaning_selection` |
| 1 | 1 | 1 | `recursive_policy` |

同一 seed 的 8 组共享初始数据与预算。首轮候选池和待反馈候选—反馈配对共享；之后允许按策略分支。记录每组每轮实际发生的状态变化，不能只按配置中的“enabled”推断更新已生效。

### 主要分析

- 以 seed 为单位、先对轮次按预注册规则聚合，再计算 S、C、Q 三个边际主效应和 S×C、S×Q、C×Q、S×C×Q 交互。
- 主结果采用 development 最终轮；完整分析脚本同时输出每 seed 效应、均值、区间和每个单元格样本数。
- 对 7 个预设效应做 Holm 校正；pilot 单 seed 只检查管线和符号，不作显著性结论。
- 更新触发率作为机制指标：每模块统计触发轮数、no-op 轮数、版本差异、引用的反馈 query IDs 和产生的候选变化。

### 呈现

8 组 seed-level 点图/区间图；三主效应和四交互的系数森林图；轮次策略状态变化矩阵；预算平衡表。禁止只展示 4 组逐项冻结后就声称估计了交互效应。

## QA-3：反馈选择在固定候选池和预算下是否有效

### 假设

当待评候选相同时，按反馈价值选择在相同反馈数量下，较随机选择或单纯不确定性选择获得更高的后续效果/单位反馈成本。

### 主实验（隔离选择器效应）

1. 每 seed 仅生成并清洗一份候选池，保存不可变候选清单及哈希。
2. 在同一候选池上运行 `query_random`、`query_uncertainty`、`query_feedback_value` 三种选择；候选数固定 32，反馈数固定 16，隔离样本配额相同。
3. 三种方法都使用同一反馈标注来源与版本。模型模拟阶段只比较方法行为；正式效率/偏好实验用真人标注。
4. 主分析限定一轮：三组在完全相同候选池中选不同样本，避免后续生成策略变化混入“选择器”效应。另做 3 轮递归延伸分析，标为长期系统效果，不与主选择器效应混为一谈。
5. 人工标注者看不到选择方法、候选分数、模型组名；候选顺序随机化。允许 usable / needs_revision / unusable / cannot_judge，并记录耗时。

### 指标

- 主指标：相同 16 条反馈预算下，最终 outcome-evaluation pairwise accuracy；真人版本同时报告每分钟 actionable feedback 数、每条有效反馈秒数。
- 次指标：反馈类别分布、actionable 比例、query uncertainty、affected candidate count、选择覆盖的 source group 数、标注者间一致性。
- 分析：按 seed 配对；按 source group 聚类 bootstrap；报告随机选择多个预先冻结的随机种子，不能只挑一个有利随机样本。

### 呈现

三选择策略 seed-level 配对图；单位成本效果散点图；反馈类别堆叠柱图；选择覆盖和一致性表。若真人数据量不足，只报告 pilot 描述值。

## QA-4：少样本适用性

### 要回答的问题

当初始可用数据很少时，完整递归策略是否仍能改善任务效果；随着初始数据量增加，递归策略的额外收益是否减小。

### 实验组和数据量

每个 seed 使用嵌套的初始 seed group，保证低预算数据包含在中预算中，中预算包含在高预算中。建议先固定三档：`low`、`medium`、`high`，具体 group 数写入配置并在运行前冻结，不能看完结果后调整。

每档分别运行：

| 组 | 策略更新 | 作用 |
|---|---|---|
| `fixed_policy` | 关闭 | 数据量变化下的固定流水线基线 |
| `recursive_policy` | 开启 | 数据量变化下的 Aladdin |

所有档位使用相同 development evaluation groups、相同候选数、反馈数量、训练记录数、token 预算和训练参数。只有 seed group 数量变化。所有组仍按“合成—清洗—选择—反馈—更新—训练”运行。

### 主要指标和分析

- 主要指标：每个数据量档位、每个 seed 最后一轮的 development pairwise accuracy。
- 主要效应：同一 seed、同一数据量档位下 `recursive - fixed` 的配对差。
- 交互效应：`策略类型 × 初始数据量`，回答递归方法在少样本时是否更有帮助。
- 次要指标：达到固定效果所需的反馈数、训练 token、候选保留率、有效反馈率和总耗时。

### 对照和呈现

使用嵌套 seed groups 和相同 seed 配对，避免不同样本组成造成误差。呈现数据量—效果曲线、三档配对增益表、数据量—反馈成本曲线。该实验不能证明“数据越少一定收益越大”，只检验预先声明的交互方向。

### 当前状态

数据预算 sweep runner 已提供；同 seed 下由固定随机排列的前缀构成嵌套 seed groups。Smoke 报告逐档结果和 `recursive - fixed` 的 seed-level development 差。正式分析还需按冻结的低/中/高预算与多个 seed 估计策略×数据量交互。

## QA-5：需求逐步明确

### 要回答的问题

用户开始时只能给出不完整要求，后续通过反馈逐渐补充要求时，递归数据策略能否更快满足新要求，同时保留旧要求。

### 受控任务设置

使用可自动判定的要求，先验证格式和长度等客观要求，再扩展到需要盲评的主观要求。每个任务预先定义要求序列，例如：

```text
第 0 轮：回答问题并保持事实正确
第 1 轮：新增“回答不超过指定长度”
第 2 轮：新增“使用指定格式”
```

要求释放轮次、要求文本、自动判定规则和测试样本在实验前冻结。不能根据运行结果临时增加要求。

### 实验组

| 组 | 要求获得方式 | 数据策略 |
|---|---|---|
| `fixed_policy` | 按轮次获得新增要求 | 不更新数据策略 |
| `recursive_policy` | 按轮次获得新增要求 | 根据反馈更新合成、清洗、选择 |
| `full_requirement_reference` | 第 0 轮获得全部要求 | 作为信息充分的参考，不作为公平主基线 |

三组使用相同任务模型、候选预算、反馈预算、训练预算和评价样本。参考组用于回答“如果一开始就知道完整要求，效果是多少”，不能直接解释为真实用户可获得的上限。

### 主要指标和分析

- 新要求满足率：新增要求出现后，每轮满足该要求的比例。
- 旧要求保持率：新要求出现后，之前要求仍被满足的比例。
- 联合满足率：旧要求和新要求同时满足的比例。
- 适应速度：从要求释放到达到预先冻结的满足率门槛所需的轮数或反馈数。
- 适应成本：适应期间的反馈 token、训练 token、人工时间或模型调用时间。

主要比较是 `recursive_policy` 与 `fixed_policy` 的配对差；`full_requirement_reference` 只作参考。呈现要求释放标记的逐轮曲线、旧/新要求满足率表和适应成本表。

### 当前状态

runner 接受 `requirement_schedule`，包括唯一 ID、release round、要求文本和客观 criterion（`contains`、`starts_with`、`max_chars`）；要求在指定轮次反馈后进入策略更新。`full_requirement_reference` 从第一轮获得全部要求。当前 compliance 指标评价合成候选文本是否满足已释放的客观要求；正式实验还需要预注册多条要求、旧要求保持分析和独立下游任务评价，不能把候选文本合规率单独解释为用户需求适应或模型能力提升。

## 支撑验证 A：Qwen3-32B 模拟反馈与真人反馈的一致性

### 目的

测定模拟反馈与真人判断的一致程度和偏差。未通过该实验前，Qwen3-32B 只作为流程压力测试，不得把它当真人代理或用其结论推断真实人工成本。

### 操作

1. 从 PRISM seed/development 之外的本实验候选中，按清洗状态、模型判断类别和选择分数分层随机抽样；样本数由先导标注估计一致率区间精度后冻结。
2. 每条样本由 Qwen3-32B 与至少 3 名匿名真人独立判断；真人不知道模型标签和其他人答案，模型提示与版本冻结。
3. 对齐 `judgment`、`issue_code`、`requirement_clarity`、是否提供 correction/new requirement；比较模型与多数票及各真人，不把多数票宣称为绝对真值。
4. 报告类别混淆矩阵、macro-F1、balanced accuracy、Krippendorff's alpha/适用的一致性统计、actionable precision/recall、修订文本盲评质量；报告每位真人耗时分布。

### 决策

预注册每项可接受的一致性下限与置信区间宽度后再收集正式样本。若下限未达到，不用模型反馈支持真人偏好结论；保留模型反馈作为单独模拟条件，并继续真人主实验。

## 支撑验证 B：鲁棒性、成本与递归稳定性

### 操作

- 数据量：按 seed 数据组数预先设定低/中/高预算（例如默认 seed-group limit 的 0.5×、1×、2×，上限受可用数据限制），报告性能与成本曲线；比例和实际组数写入冻结配置。
- 反馈预算：固定候选池，比较 8/16/32 条反馈预算；所有选择策略使用相同预算点。
- 反馈噪声：在副实验中按预先声明的比例注入错误标签/错误修订（0%、10%、20%）；只用于敏感性分析，不能改写主实验反馈。
- 延迟与故障：在调用层模拟超时、无效 JSON、非法枚举、重复响应、进程中断；验证 attempt 成本完整、幂等恢复、策略版本与反馈 query lineage 一致。
- 递归稳定性：至少 5 个 seed、每 seed 多轮；报告性能变化、策略更新/no-op、清洗保留率、反馈类型漂移、候选重复率和崩溃恢复。5 seed 仅为最低 pilot 覆盖，不自动等于有足够统计功效。

### 报告

预算—效果曲线、噪声敏感性曲线、更新轨迹图、故障注入通过率表、每 seed 运行完整性清单。仅对预注册主要对比做确认性推断。

## 统计与最终测试协议

- pilot 后用 seed-level paired outcome 估计标准差；在看正式结果前指定 `delta_min`，按双侧 alpha=0.05、power=0.80 计算 seed 数，并记录计算代码/参数。若资源不足，明确降级为探索性研究。
- 多轮不是独立样本；多个 seed 是主要重复单位。成对方法使用同一 seed、同一 source-group 划分和同一开发评价样本。
- 主结果报告点估计、95% CI、效应量、原始分母、缺失/失败 run 数；小样本同时报告逐 seed 数据，不以 bootstrap 区间掩盖 seed 太少。
- final-test 在所有代码、模型、策略、阈值、seed 和分析冻结后，由独立命令生成盲评队列。至少 3 名真人独立评价每个 pair；覆盖 A/B 随机化、both acceptable/neither/cannot judge、评审耗时和一致性。测试标签不进入策略更新或任务训练。
- final-test 输出先锁定预测和盲评反馈，再由独立 key 解盲分析。保留 queue、key、反馈和分析文件哈希。

## 运行顺序与当前可执行性

1. 支撑验证 A：完成数据/日志不变量和清洗审计集准备。
2. 实验一：运行整体 RSI 单 seed rehearsal；通过后做 pilot seeds 和功效分析。
3. 实验二：运行 8-arm factorial pilot；确认每类更新确实触发，再冻结正式 seeds。
4. 实验三：先跑单轮固定候选池主实验，再跑 3 轮递归延伸实验。
5. 实验四：实现并运行嵌套 seed-group 的低/中/高数据量比较。
6. 实验五：实现要求序列、逐轮评价器和参考组，再运行需求逐步明确实验。
7. 支撑验证 A：收集模型/真人成对反馈，估计模拟反馈效度。
8. 支撑验证 B：运行预算、噪声、故障和递归稳定性实验。
9. 所有正式训练和分析完成后，执行一次 final-test 盲评。

当前代码已提供实验一至实验三的 smoke 路径：整体对照、8-arm factorial、固定池选择。Smoke 使用小数据/小 token 配置，只验证链路、resume/记录和指标可计算；实验四、实验五的 runner 仍作为后续实验实现草案保留。正式研究仍需多 seed、统计功效、真人反馈与 final-test 盲评。

开跑完整研究前仍须准备：真人清洗审计标签；QA-4 真人反馈与一致性数据；功效分析需要的 pilot seed-level 方差和 `delta_min`；final-test 的独立真人盲评者。上述内容不能由模型生成来冒充。实验三正式主分析要用单轮固定候选池配置；现有通用 selection 配置的三轮运行只能作为递归延伸分析。
