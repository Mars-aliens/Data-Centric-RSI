# 实验设计：验证反馈驱动的数据策略更新

> 当前执行配置：第三阶段使用固定 Qwen3-32B（revision `9216db5781bf21249d130ec9da846c4624c16137`）模拟反馈，每组每轮按 `query_count_per_arm_round` 固定评审条数。下文人工分钟和真人效果属于后续真人验证协议，不能用于解释当前模拟结果。当前记录模型调用次数、token、耗时和失败尝试；final-test 使用 Qwen3-32B 自动盲评，真人入口作为可选功能保留。


## 研究目标

验证一条完整的数据流水线能否利用有限的人类反馈，持续改进后续轮次的数据策略和生成任务效果。研究重点是“反馈是否带来可归因的递归改进”，不是只比较哪一种静态合成方法得分最高。

本研究不以提出新的合成器或清洗器为目标。阶段一采用改造版 Self-Instruct，阶段二采用确定性规则清洗；阶段三以随机和不确定性选择为基线，并检验 Aladdin 的反馈价值选择方法。论文的核心比较是固定策略流水线与反馈驱动的递归流水线，以及相应的策略更新消融。

所有实验条件都从同一份少量 seed 开始，但 `seed-only` 不作为主实验必跑组。只有当研究问题另行扩展为“完整数据流水线是否优于完全不扩充的 seed 数据”时，才加入该参考组。

固定运行流程为：

```text
少量初始样本
  -> 数据合成（自动）
  -> 数据清洗（自动）
  -> 选择值得询问的样本
  -> 收集人工反馈
  -> 更新下一轮的数据合成、数据清洗和反馈选择策略
  -> 进入下一轮
```

人工反馈只在第三阶段、样本被选中后收集。第一阶段和第二阶段不要求人逐条判断。第三阶段得到的反馈用于下一轮，不能倒流修改已经完成的本轮合成或清洗。

## 三阶段方法与基线

主实验的组件选择固定如下。固定策略组与递归更新组从同一套初始方法和配置出发；研究重点是反馈驱动的策略更新，不是单独证明某个组件优于所有同类算法。

| 阶段 | 固定采用的方法 | 对照中的角色 |
|---|---|---|
| 数据合成 | 改造版 Self-Instruct：从少量 seed 生成新任务输入，再生成对应回答 | 作为两种系统组共同使用的合成基线；递归组可依据上一轮反馈更新提示词、示范和生成配置。该实现是任务适配，不称为原论文完整复现。 |
| 数据清洗 | 确定性规则清洗：格式/schema 检查、空内容和无效续写过滤、精确去重及冻结阈值的近重复过滤 | 作为两种系统组共同使用的清洗基线；拒绝项保留在隔离池供第三阶段抽查，递归组可依据反馈更新预先允许的规则或阈值。 |
| 数据选择与反馈 | 反馈价值选择作为整体对照和递归更新消融的初始策略；随机选择、不确定性选择作为实验三的对照 | 三种方法都先选出待评审样本，再收集真人反馈。人工反馈不是数据选择本身；它只在样本选中后产生，并用于下一轮更新。 |

因此，整体对照两组使用同一套初始组件：改造版 Self-Instruct、确定性规则清洗、反馈价值选择。固定组始终保留这三个初始策略；递归组每轮收到反馈后，才可更新下一轮的合成、清洗和反馈价值排序策略。反馈价值选择是 Aladdin 的待检验方法，不是外部 baseline；随机和不确定性选择是实验三中的外部查询基线。

主实验不把固定提示词、Evol-Instruct、LLM 质量 judge 或 `seed-only` 加入必跑矩阵。它们可用于单独的组件预检或后续扩展，不作为当前 RSI 主假设成立的前提。近重复阈值、生成预算、选择器模型与评分公式须先在 development 上预检，再于正式运行前冻结；这些参数目前不是实验验证结论。

## 核心假设

- **H1 整体收益：** 在相同人工分钟、生成量和训练预算下，反馈驱动的递归流水线比策略固定的流水线获得更好的独立盲测输出评价。
- **H2 更新作用：** 完整更新优于分别停止合成、清洗或反馈选择更新的消融组；差值用于估计各更新模块的边际作用。
- **H3 查询价值：** 相同人工分钟下，反馈价值选择比随机和不确定性选择产生更高的后续盲测收益或更多可执行的数据策略变化。

H1 是系统主假设，H2/H3 用来定位作用来源。它们都是待检验假设，不是现有结果。

清洗器必须同时保存保留池和隔离池（被清洗器拒绝的候选及其拒绝原因）。第三阶段的反馈选择池应包含两者，并预先固定抽查隔离池的预算或比例。否则系统只会看到清洗器已经保留的数据，无法发现误删，也无法验证反馈是否改进了清洗策略。隔离池样本只有经过第三阶段反馈后，才可按预先写明的规则恢复或继续隔离。

## 实验一：整体对照

比较固定数据流水线与反馈驱动的递归流水线，回答递归更新是否带来额外收益。

| 组别 | 数据策略 | 人工反馈 | 反馈用途 |
|---|---|---|---|
| 固定流水线 | Self-Instruct、确定性清洗、反馈价值选择均保持初始版本 | 每轮使用与递归组相同的人工分钟预算 | 反馈可按相同规则进入任务模型训练；不改变下一轮的数据策略 |
| 递归流水线 | 从相同初始组件出发，按每轮反馈更新合成、清洗和反馈价值选择策略 | 相同的人工分钟预算和标注流程 | 更新下一轮三类策略，并按相同规则进入任务模型训练 |

两组使用相同初始数据、模型版本、轮数、每轮候选预算、清洗计算预算、任务模型训练 token 预算、反馈收集时间和开发集。两组都按相同规则把收到的反馈用于任务模型训练；只有递归组能据此改动下一轮的数据策略。这样比较的是数据策略递归更新的额外作用，避免把多收集反馈或多训练模型误当作 RSI 收益。至少运行两个更新轮次。

递归组的更新范围是三个有版本的策略：合成提示词/示范及生成配置；清洗规则、阈值及隔离判定；反馈选择的打分参数或排序规则。每轮只允许使用本轮第三阶段实际释放的反馈，保存修改前后配置和对应反馈事件。固定组也执行相同的合成、清洗、查询和训练流程，但继续使用初始策略版本。

合成器和清洗器可直接选定已有 baseline，固定流水线组与递归组从完全相同的 baseline 和初始配置出发。无需为证明“某个 baseline 最好”而单独运行完整模型比较矩阵；需要做的只是小规模接口、预算和输出格式预检，并在论文中准确引用及说明任务适配。

| 更新对象 | 反馈依据 | 下一轮允许修改的内容 |
|---|---|---|
| 合成策略 | 人工指出的缺失要求、候选修改和被确认可复用的示范 | 生成提示词、要求摘要和示范样本 |
| 清洗策略 | 保留池及隔离池抽查反馈、问题原因 | 已预先允许的清洗规则或阈值；每次改变都记录影响范围 |
| 反馈选择策略 | 某次查询是否带来可执行的新要求/修改，以及真实评审耗时 | 反馈价值打分的权重或排序参数 |

正式运行前冻结各策略允许修改的字段、更新算法和审核规则。任何更新都不能用 final-test 结果作依据；没有足够反馈支持变化时记录 no-op。

## 实验二：更新消融

比较完整更新与逐项冻结，判断每类更新对整体收益的作用。

| 组别 | 合成策略更新 | 清洗策略更新 | 反馈选择策略更新 |
|---|---:|---:|---:|
| 完整更新 | 是 | 是 | 是 |
| 停止合成更新 | 否 | 是 | 是 |
| 停止清洗更新 | 是 | 否 | 是 |
| 停止反馈选择更新 | 是 | 是 | 否 |

三个消融组与整体对照使用相同初始版本、更新规则、轮数、反馈分钟预算、候选/训练预算和评价集。冻结某一项时，只冻结该模块的策略版本；其他模块仍按同一规则更新。固定流水线组可作为“三项均停止更新”的参照，不必重复运行。

消融对照统一从实验三预先选定的主选择方法开始；在反馈价值方法作为 Aladdin 主方法的设定下，完整组可以根据反馈调整价值排序参数，“停止反馈选择更新”组保持初始参数不变，其余更新行为一致。

这里的“反馈选择策略更新”是指下一轮查询优先级或其参数是否会根据上一轮反馈而变化；它不同于每一轮都执行的“选择样本给人评审”操作。消融前要把可更新状态及其更新规则写进配置和日志，不能只用组名代替实现定义。

## 实验三：反馈选择对照

在相同候选池和相同累计人工分钟预算下比较三种查询方法，回答哪种方法获得的反馈更能改善后续数据和任务效果。

| 方法 | 查询规则 |
|---|---|
| 随机选择 | 从当前可评审池均匀抽样，使用固定随机种子。 |
| 不确定性选择 | 优先选择偏好模型对候选判断最不确定的样本；采用预先固定的概率熵或成对分差指标。 |
| 反馈价值选择 | 优先选择预计能改变后续数据策略、影响更多候选且单位评审时间价值较高的样本。 |

当前代码将反馈价值实现为 `偏好熵 × (1 + impact_weight × log(1 + 同源候选数)) ÷ 预计评审秒数`。这些分量只使用查询前可见的信息；它是待验证的代理分数，不应称为已校准的真实效用。真实评审秒数在第三阶段记录；选择下一条查询前同时检查已用时间和预计时间，单次评审仍可能超过目标预算，超出秒数须如实报告。

每个 seed 的首轮由当前比较中的第一组生成一次候选池，其他组复用相同候选文本并使用各自的记录 ID，生成成本只计入首轮池的 owner 组。后续轮次才允许因反馈产生不同策略和候选。各方法使用相同的清洗规则和隔离池查询配额。选择器更新在三种策略对照组中冻结，合成与清洗更新规则保持一致；这样比较“选哪些样本询问”的影响。隔离池抽查比例在运行配置中固定，pilot 默认 25%，正式实验前须冻结。比较每人工分钟获得的可用反馈、能引发的数据策略变化、下一轮 development 表现和最终盲测表现。

第三阶段记录可用于更新的反馈字段：候选是否可用、主要问题类型、要求是否清晰、可选修改/新要求及实际评审耗时。允许“无法判断”和并列，不能强迫选择者给出不符合真实判断的标签。研究对象若是特定用户，结果只支持该用户的个性化效果；若要作群体层面的结论，需招募多个目标用户/独立评价者并按用户聚类分析。

## 数据、反馈与评价边界

- 按用户、对话或原始任务组划分数据；同一来源及其所有合成派生记录只能属于一个 split。
- 初始 seed、反馈候选池、开发集和最终测试集职责分开。查询前隐藏候选对应的反馈标签；最终测试在协议、方法和阈值冻结前不得读取。
- 每条人工反馈记录查询 ID、候选/来源 ID、选择方法及版本、轮次、判断、原因、可选修改、需求清晰度、匿名标注者 ID、显示顺序和真实耗时。允许“都可以”“都不合适”“无法判断”和不同标注者意见不一致。
- 每次策略更新记录输入反馈事件、修改前后版本、具体变化、依据、确认状态，以及下一轮受影响的候选 ID。没有足够依据时记录不更新，不为制造递归而强行改策略。
- 主要结果采用未参与策略更新的独立评价者，在封存测试任务上盲测输出偏好；报告胜/平/负、不确定性和标注者一致性。开发集用于逐轮诊断，不能替代最终盲测。
- PRISM 或 HelpSteer2 的既有标签可用于离线回放和开发集检查，不能冒充对新合成样本的真人反馈，也不能证明真实人工耗时降低。选择方法的真实成本结论需要第三阶段真人评审和计时。

## 主要结果与诊断指标

主要结果是在相同累计人工分钟、生成/清洗/训练预算下，比较各轮及最终盲测任务效果。另报告每人工分钟带来的有效反馈、实际评审时间分布、策略更新次数及来源、候选独特率、合成覆盖、清洗保留/隔离比例、隔离池抽查结果、模型训练成本和总 API 成本。

样本量、随机种子数、每轮候选量和人工分钟预算应先用小规模计时及方差估计确定，再冻结到运行配置；当前不把尚未完成的预算试跑写成确认性设置。

## 当前实现状态

PRISM 主 runner 已覆盖整体对照、三类策略更新消融、反馈选择对照、真人反馈采集/计时、多轮 Qwen LoRA development 评价和独立 final-test 盲评入口。代码可运行工程 pilot；GPU/API 运行、真实标注、标注一致性分析及确认性预算尚未完成验证或冻结。人工反馈只发生在第三阶段样本选出之后。
