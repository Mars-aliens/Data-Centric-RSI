# 技术二：可执行经验生命周期管理

状态：经验生命周期接口骨架已实现；研究策略、真实运行适配和长周期实验尚未完成。

技术二研究 Data System 如何把经过验证的运行经验转成可执行、可追溯、可失效的 Memory 和 Skill，并在长周期运行中避免错误经验累积、经验冲突和无界增长。

规划中的核心机制：

- 记录经验的来源数据、模型、评价版本、Harness 版本和适用条件；
- 将通用判断与具体配置分开保存，避免把一次成功直接推广到所有任务；
- 检索前进行条件匹配、权限检查和预算检查；
- 对重复失败、数据分布变化和模型变化触发降权、失效或重新验证；
- 控制 Memory/Skill 的规模、版本和恢复点；
- 将可执行经验的收益与错误累积、调用成本、恢复时间一起评估。

技术二必须复用 `core_system.mle_core` 的版本、预算和事件契约，不得重复实现技术一的 Harness 候选评估机制。其对照至少包括只保存文字反思、不复用经验和可执行经验复用三种方式，并在短期质量与长周期稳定性上同时比较。

当前 `ExperienceLifecycleStore` 提供带来源与条件的经验记录、显式验证、条件变化失效、重复失败转待验证、冲突隔离/解决及只检索已验证匹配经验。它是可测试的框架起点，尚未包含语义检索、自动冲突发现、有效期学习或规模治理算法。
